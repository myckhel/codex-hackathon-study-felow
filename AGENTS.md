# Repository guidance

For hackathon project work, read `PROJECT_MEMORY.md` before making product or architecture decisions. Keep that file current as durable project facts, decisions, scope, status, and next steps change. Favor a coherent, demonstrable vertical slice within the stated one-week timebox; make risks and tradeoffs explicit and avoid expanding scope without a clear judging or user-value reason.

When the user shares a study-group contact reply or asks for a tailored StudyFellow invitation/tracker update, follow `outputs/study-group-outreach-workflow.md`.
